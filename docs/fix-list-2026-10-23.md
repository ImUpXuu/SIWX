## 一、P1（发布阻断，7 条）

### P1-1 打包版 wxgf 转码子进程永远失败

- 位置：`siwx/media.py:301-306`、`run.py`、`siwx/cli.py:177`
- 触发：运行 PyInstaller 打包的 exe（Release 推荐分发方式），消息含 wxgf 图片。
- 影响：`sys.executable` 是 exe，`run.py` 进入 `cli.main()`，argparse 没有 `-c`，子进程必然非零退出；无回退。所有 wxgf（表情、封面、部分图片）在打包版不可见；每次重试还会重新解包 onefile。
- 修法：为 worker 增加独立入口（spec 里加第二个 EXE，或改用 `multiprocessing` 子进程）；仅源码态用 `-c`；失败日志区分 frozen/源码。
- 验收：打包 exe 对一张 wxgf 样本转码成功；源码态回归不退化；新增 frozen 冒烟。

### P1-2 macOS 打包版 `inspect.getsource()` 取不到源码

- 位置：`siwx/media_wxgf_macos.py:109-110`、`siwx/media.py:570`、`siwx/media_backup.py:121`
- 触发：macOS `.app` 中遇到 wxgf，单图请求或全量备份转码阶段。
- 影响：模块导入时执行 `inspect.getsource`；frozen 下没有 `.py` 源文件，抛 `OSError`。单图请求 500；备份第一遍完成后转码阶段中断。
- 修法：把三个解码函数源码改为模块内常量（或随包携带 `.py` 并在 import 失败时降级）；`_finalize` 与备份转码加 try/except。
- 验收：macOS 打包产物对 wxgf 单图与批量备份均不再抛未捕获异常；源码态测试保持通过。

### P1-3 macOS LLDB 转码每次会话泄漏约 24MB 到微信进程

- 位置：`siwx/media_wxgf_macos.py:226-233`、`siwx/media_wxgf_macos.py:458-463`
- 触发：macOS 单图 wxgf 浏览或批量备份。
- 影响：每次 LLDB 会话在目标微信进程 `malloc` 8MB + 16MB + 8B + 64B，全文件无 `free`；单图路径每张图新建一次会话。浏览 100 张约 2.4GB，可能把微信拖到 OOM。
- 修法：脚本所有退出路径 `free` 四个指针；单图路径复用同一 attach 会话或改为批量；补超时/失败清理。
- 验收：连续转码 N 张后目标进程内存不随张数线性增长；批量路径仍正常。

### P1-4 TOML 导出不是合法 TOML

- 位置：`siwx/exporter.py:940-946`、`siwx/exporter.py:562-570`
- 触发：任意 `fmt="toml"` 导出。
- 影响：`isGroup = True` 直接拼进 header；TOML 只接受小写 `true/false`，`tomllib` 解析报错。8 种格式中的 TOML 完全不可用；现有测试只断言文件存在。
- 修法：布尔值显式输出 `true/false`（或统一走 TOML 值序列化）；补 `tomllib.loads` 回归。
- 验收：导出文件可被 `tomllib` 解析，session 与 messages 字段均可读。

### P1-5 导出 HTML 的搜索入口不可达

- 位置：`siwx/templates/default/renderer.js:846-860`、`siwx/templates/default/head.html:292/297`
- 触发：打开任意导出 HTML，点页头放大镜。
- 影响：`7e2d171` 删除了 `searchToggle` 的 click 监听；`#searchBar` 始终 `display:none`，全文件只有 `searchClose` 执行 `remove('active')`，没有任何添加点。搜索输入、上一处/下一处、关闭均不可达。
- 修法：恢复 `searchToggle` 监听（toggle `.active` + focus），补 Enter 打开；`searchClose` 仍能关闭。
- 验收：导出 HTML 点击搜索按钮出现输入框，输入关键词能高亮/跳转；补一条 DOM 冒烟测试。

### P1-6 发布闸门在 Release 之后才校验 tag 与版本号

- 位置：`.github/workflows/release.yml:93`、`.github/workflows/release.yml:137-157`
- 触发：打 tag 但 tag 与 `siwx.__version__` 不一致，或发版时忘记同步版本。
- 影响：`version-json` job `needs: [release]`，Release 先公开；tag/版本不一致只会在最后失败，`version.json` 不更新，自动更新链看不到该版本。test job 只钉版本字面量，不校验 tag。
- 修法：把 tag ↔ `__version__` 校验前移到 test/build 前置 job；`version.json` 生成放到发布前；release 依赖校验通过。
- 验收：故意用不匹配的 tag 跑 workflow，在 build 前失败；正常 tag 的 Release 与 `version.json` 同步。

### P1-7 macOS 交付物与文档承诺不符

- 位置：`.github/workflows/release.yml:63-91`、`packaging/siwx-mac.spec:59-69`、`MACOS_SUPPORT.md:54`
- 触发：从 Release 下载 macOS DMG。
- 影响：spec/workflow 未声明 `target_arch`/`universal2`，产物架构取决于 runner；文档却写明 Intel Mac 12.7.6 已实测。同时没有 codesign/notarytool，DMG 未签名未公证，Gatekeeper 会拦，README 无右键打开/去隔离说明。
- 修法：明确产物架构（arm64-only 或 universal2）；需要 Intel 就加 x64/universal2 构建；加 codesign/notarytool，或在文档写清未签名安装步骤；同步 `MACOS_SUPPORT.md` 与 `README.md`。
- 验收：Intel 与 Apple Silicon 各启动一次；Gatekeeper 流程按文档可走通；`version.json` 的 macos asset 名与架构一致。
