## 三、导出格式转换（JSON → 各格式）

### 背景结论（2026-10-11 已逐行核对，维持成立）
JSON 导出包含全部下游格式所需字段（含 `rawContent`/`quote`/`link`/`record`/`mediaFile`——后者由 `_attach_media` 在写入前对包括 JSON 在内的全部写入器统一回填——与媒体定位四件套 `md5`/`bubbleMd5`），**JSON → HTML/MD/TXT/CSV/TOML/SQLite/XLSX 均可无损转换，无需重跑解密**。`_script_safe_json`、`esc()`、`safeUrl()` 等转义层逐分支核对无注入面。
- **警示**：`siwx/export_stream.py:23` 的 `_KEEP_FIELDS` 白名单（"精简消息、去 rawContent 重复"）是**从未接线的死代码**，JSON 实际写全量字段。若将来有人把它接上，本节"JSON 无损转换"前提即被打破——接线前必须先评估对转换器的影响。

### 4. 方案 B：离线转换脚本（✅ 本轮已实施）
- `siwx/json_export_convert.py`：对已有导出目录（每个会话目录 = `manifest.json` + 会话 JSON + `media/` + `avatars/`）就地补生成 Markdown 与 HTML，单会话 `json.load`、逐会话处理并释放；复用管线现有写入端（`stream_export_md` 契约、`html_template` 渲染契约）；`mediaFile` 存在性校验，缺失计入结果提示；manifest 沿用原 parse/media 段、追加转换段。
- 用法：`python -m siwx.json_export_convert <export_dir> [--formats md,html] [--only N] [--template default] [--overwrite]`
- 回归：`tests/test_json_export_convert.py`（5 用例：同名输出/消息数对账/manifest 口径/跳过与重写/坏目录）。
- 实测（2026-10-11）：1248 会话全量转换 0 失败、0 媒体缺失引用；私聊与群聊样本经真实浏览器渲染核对（文件卡/链接卡/系统消息/头像回退/懒加载均与原生导出一致）。

### 5. 方案 A：结果面板一键"补生成格式"（✅ 已实施，2026-10-17 `dac8492`）
- 导出完成后在结果面板提供"从此目录追加生成：Markdown / HTML / TXT / CSV"按钮；后端复用方案 B 的转换模块（同一份 `json.load` → 消息流 → 写入器代码路径），前端只加按钮与进度接线。
- 头像映射按 `avatars/md5(username).jpg` 确定性规则重建；faces/maps 从消息重提取。

### 6. Markdown 写入端不做转义（格式天性，原生导出同样存在）
- 多行消息后续行以 `#`/`-`/`*`/`1.`/`>` 开头会被 MD 渲染器劫持成标题/列表/引用；单独一行 `---` 变水平线；行内 `*斜体*`、`[文字](链接)` 被误解释。
- **决策（2026-10-17 维护者拍板）：维持不转义**——转义让 MD 源文件难读，格式天性的误解释可接受；离线转换脚本与原生导出同口径（不转义），两条线继续一致。

## 四、JSON → X 转换的注意点（实现时逐条落实）

7. **media/ 目录前提**：`mediaFile` 是会话目录内相对路径；目录被搬丢/删改后转换出的 HTML 全是裂图。✅ 转换脚本已做存在性校验并把缺失计入提示。
8. **大 JSON 整包解析内存**：原生导出 O(1) 流式；`json.load` 整包在 12 万条级会话占数百 MB。✅ 转换脚本按单会话加载、逐会话释放；必要时再上增量数组解析。
9. **manifest 口径**：parse 统计与媒体失败分布无法从 JSON 重算。✅ 转换脚本沿用原 manifest 的 parse/media 段，只追加 `converted` 段记录转换产物与缺失媒体计数。
10. **联网依赖**（与原生一致）：位置瓦片（wx_maps）与未下载成功的 type-47 表情（CDN 兜底）转换时同样走在线获取，离线退化为占位。脚本在离线环境下不应因此失败（容错为占位）。
11. **范围即所信**：转换产物 = 原 JSON 的会话/日期范围快照，不会"扩回"未导消息；UI 文案需说明。
12. **机会点**：JSON 里的媒体定位四件套使得"只补媒体、不重扫消息"的增量补媒体可行，可作为方案 A 的后续。
